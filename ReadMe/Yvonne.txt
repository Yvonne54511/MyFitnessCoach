=== (補充) 技術說明 ===

- ILogger<T>:
  * 用途: 內建日誌記錄工具，用於追蹤程式執行狀態或記錄錯誤。
  * 範例: 在 Service 中捕捉 Exception 後，使用 _logger.LogError(ex, "Message") 記錄錯誤詳細資訊。

- PasswordHasher<User>:
  * 用途: 安全地處理密碼雜湊與驗證，符合資安標準(不存明文)。
  * 非靜態類別，需實例化後使用。
  * HashPassword(): 用於將新密碼轉為雜湊值(如重設密碼時)。
  * VerifyHashedPassword(): 用於登入時比對明文密碼與資料庫中的雜湊值是否相符。

-IPasswordHasher<User>:DI注入介面，可用來單元測試時增加假的雜湊方法。

-AsNoTracking()
GetByEmail 沒有加 .AsNoTracking()，但 GetByAccount 有加，這是因為：
•	.AsNoTracking() 會讓查詢結果不被 EF Core 追蹤（只讀、效能較佳，不能直接修改）。
•	沒加 .AsNoTracking()，查詢結果會被追蹤（可直接修改屬性並呼叫 SaveChanges() 更新資料庫）。
用途差異：
•	如果你只是查詢資料、顯示用，建議加 .AsNoTracking()。
•	如果你查詢後要修改這個物件（例如重設密碼、更新資料），就不要加 .AsNoTracking()，這樣 EF Core 才能追蹤物件的變更。
在這個 AccountRepository 裡：
•	GetByAccount 只查詢帳號（可能只讀），所以加了 .AsNoTracking()。
•	GetByEmail 可能查出來後要修改（如重設密碼），所以沒加 .AsNoTracking()，讓 EF Core 可以追蹤並更新。
